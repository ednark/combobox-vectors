How It Works

The options are real federal policy documents and government agencies with deliberately opaque titles — numbers, acronyms, and department names that substring typeahead cannot structurally match to user intent. Ranking runs two retrieval channels and fuses them:

  • Dense: cosine similarity between the query embedding and each option's vectorText embedding (keywords + summary body — text the user never sees). Captures topical similarity: "hackers stealing data" → OMB M-22-09. Both embeddings are computed client-side with the same model, guaranteeing a shared vector space.
  • Sparse: BM25 with IDF weighting over the title (boosted ×3) and vectorText, with each token indexed both exactly and as a metaphone phonetic key — so typo'd queries ("recods", "secuirty") still collide with the intended term. Captures exact tokens the dense channel is blind to — dates, numbers, proper nouns: "October" → EO 14110 (October 2023).

The two ranked lists are fused with Reciprocal Rank Fusion (Σ 1/(60 + rank) per channel — the same default used by Elasticsearch 8 and OpenSearch for hybrid queries). Rank-based fusion needs no score normalization: BM25 is unbounded while cosine is 0..1, and RRF sidesteps the mismatch entirely. The sparse channel is always live; the dense channel is a progressive enhancement. Toggle the switch above to isolate either mode.

Tradeoffs & Applicability

The cost of client-side inference

This demo runs an embedding model (minishlab/potion-base-4M, a Model2Vec static embedder, 15.1 MB ONNX) entirely in the browser via WASM — chosen by a corpus-relative evaluation where it beat the previous contextual transformer baseline while running inference as a single embedding lookup. No server round-trip, no embedding API, no query text leaving the device — but every user pays a one-time download per site per browser. Browser cache partitioning means the bytes aren't shared across origins, so each site re-pays the cost even for users who've downloaded the model elsewhere. On repeat visits the cached model loads in milliseconds; on a first visit over metered mobile data, it's a real cost.

Strong fit

  • High-frequency internal tools — the download amortizes to zero across daily sessions. If your users open the combobox twenty times a day, 15 MB once is noise.
  • Opaque label domains — program codes, legal citations, clinical terminology, agency names. Classic pattern: the user knows the concept but not the label. Substring typeahead fails structurally here; semantic ranking solves exactly this mismatch. The FOIA selector above is the canonical case: "who has my medical records?" → VA.
  • Privacy or compliance boundaries — HIPAA, CJIS, air-gapped networks, or any context where shipping the query to an embedding API is a non-starter. Local inference keeps the data path entirely on-device.
  • Zero-backend deployments — static sites, GitHub Pages, offline-first PWAs. Works with no search infrastructure and continues working offline after first load.

Poor fit

  • Single-visit public pages — the download never amortizes. You're taxing the 99% who won't return for the benefit of the 1% who might.
  • Small option sets — below roughly ten options, users can scan the full list faster than they can type. A native select or plain typeahead is both cheaper and better UX.
  • Bandwidth-constrained contexts — 15 MB is 15 MB, cached or not, on first load.

Mitigations built into this implementation

  • BM25 runs unconditionally — the sparse index builds synchronously at init from the same data array. Zero network dependency, so the combobox is functional on first paint, not after model load.
  • Progressive re-ranking — keyword results render immediately; when the dense model finishes loading, an open list is transparently re-ranked with RRF fusion. The upgrade is invisible unless you're watching for it.
  • Explicit kill switch — setDenseEnabled(false) short-circuits ranking to BM25-only and skips model warmup entirely, so a fresh page with vectors disabled downloads zero model bytes. Use the toggle above to A/B the two channels.
